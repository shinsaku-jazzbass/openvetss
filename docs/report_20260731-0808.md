## 全体の到達点

**サーバもインストールもなしに、動物病院の受診が一本の線で通るところまで来た。**

```
カルテホルダーのQR → 問診 → S・O・A・P → 会計 → 紙カルテ → ホルダーへ
```

土台は新規開発ではない。20年前に書かれたレジの入力文法と126キーの割当、2,626件の文例マスタ、`zeitb` の期間別税率——現場が長年検証してきた資産を、置き場所だけ変えて載せ直した。

## 日別

### 07-31（木）｜旧レジの発掘

`/vetsswebkww/regi/` を特定し、`msgnew.php`（2,200行）を解析。

**判明した主要事実**

| 項目 | 内容 |
|---|---|
| 通信 | 「先頭3文字＝出力先、4文字目以降＝値」の差分レスポンス。当時としてはサーバ駆動UIの先取り |
| 入力文法 | `[単価][*数量]A+ボタン番号+A`。テンキーだけで会計が完結 |
| 消費税 | 行別ではなく**合計に一括** `floor`。現在のインボイス要件と一致 |
| 税率 | `zeitb`（開始日・終了日つき履歴）を `dateset.php` が当日分で引く |
| 端数 | `petsct.sct_zeihasuu`（切捨／四捨五入／10円切捨／10円四捨五入） |

**指摘した問題**：保険＋税の再計算が13箇所にコピーされ `toth` の算出が5通りに分裂／`zeihasuu` を参照するのは2,200行中1箇所のみ（同じ会計から税額が2つ生まれる）／switch に `default` がなく SQL が壊れうる。

### 08-01（金）｜PHP 7.3 移行の突破

`ereg()` を一括置換し、`preg_match_match(` という壊れた関数名とデリミタ欠落を修正。**現行レジが PHP 7.3 + PostgreSQL 16 で動作。** 20年前の入力文法がそのまま生きていることを確認した。

副産物として、ePOS-Device によるレシートプリンタ制御が実装されていたこと（後日、Chrome の制限で廃止済みと判明）と、ボタンマスタが `t_key_tb` へ進化していたことが分かった。

### 08-02（土）｜オープンソース版の設計・実装

確定伝票の実データで仕様を検証（税抜5,000→税額500→税込5,500、部門別売上5,000）。

**`item` マスタ126件の正体が判明** — 物理カスタムキーボード126キーへの割当そのものだった。`item_mei` が表示ラベル、`item_dispmei` が送出コマンド文字。**キーマップがデータとして既に外部化されていた。** 単価は126件中124件が0で、簡易マスタは価格表ではなく名称辞書だった。

ネットレジ v0.1 → v0.5 を実装。

| 版 | 内容 |
|---|---|
| v0.1 | 会計・税計算・明細発行。計算は `calcTotals()` 1関数に集約 |
| v0.2 | 診察券ID・表示名、起動パラメータ |
| v0.2.1 | QRデコーダ同梱 → **iPad実機で読み取り成功** |
| v0.3 | 端末内保存・作業中会計の復帰・連番の永続化 |
| v0.4 | 日計（CSV／Excel／番号の飛び検出／複数台合算） |
| v0.5 | 自院設定の読み込み（設定ツールと対） |

技術的判断：**Excel出力を外部ライブラリなしで自作**（無圧縮ZIP＋SpreadsheetML、15KB増）。UTCで日付を取っていたため朝9時前の会計が前日付になるバグを修正。

### 08-03（日）｜サイト掲載と regix 移植の着手

トップページをネットレジ前面に改訂。**CSSで描いたiPad筐体に実物を iframe で埋め込む「LIVE」方式**を採用（撮り直し不要）。「三つの画面」セクション（iPad＝渡せる画面／PC＝並べる画面／スマホ＝持ち帰る画面）を追加。

regix 移植の方針を決定：**エンジン（`msgnew2.php`）は1行も変更せず、画面だけ差し替える。** 保険処理・カルテ書き戻し・受付連携がエンジン側にあるため。

現行の会計フローが2端末構成（`petsct` の1行をメッセージ受け渡しに使い、別端末のiPadで飼主に提示）であることが判明。同時に1台しか会計できない制約とも表裏だった。

### 08-05（火）｜regix 版の実装と修正

実機フィードバックで8件を修正。

| # | 症状 | 原因 |
|---|---|---|
| 1 | 品名ボタンが出ない | EUC-JP に `json_encode` を使い `false` が返りスクリプト全停止 |
| 2 | キー数の不一致 | キー面は 6×6＝36 ではなく **10列×6行＝60キー** |
| 3 | カスタムキーボードが使えない | 現行は「入力」キーで送信する方式。1文字ごと送信では `BC` が壊れる |
| 4 | iPad で画面崩れ | 60キーが6列＝10行必要で下段を押し出していた |
| 5 | テンキー無反応 | 数字まで即送信し、返答で入力欄が消えていた |
| 6 | 画面が急に拡大 | キー連打がダブルタップと判定 |
| 7 | 受付へ戻るが無反応 | エンジンへ送るのではなく画面遷移が正しかった |
| 8 | 精算取消ができない | `a`（ALC）は `seikeshi2.php` への遷移だった |

成果物：`sampleznewr3.php`（タッチ版レジ）、`sampleznew3.php`（患者選択）。**物理キーボードと画面の同時併用が可能**なので、移行日を決めずに少しずつ画面へ寄せられる。

### 08-07（木）｜品名別集計と、次の主題

ネットレジ v0.6：日計に「伝票別／品名別」のタブを追加。品名別は回数・数量・金額・構成比を金額降順で表示し、Excel は3シート構成に。

そして**カルテ記入ツールの検討が始まった。** VetssWeb には「何時・何処で・何が・如何した」をボタン化したカルテ記載が既にあり、レジと構造が同じだと分かった。

### 08-08（金）｜カルテ・受診ハブ・営業日

**文例マスタの解析** — `syori2` 2,626件、`syori1` 160件。

| 親ID | 区分 |
|---|---|
| 0〜19 | 主訴（健康チェック・消化器・呼吸器…） |
| 20〜39 | 所見（一般症状・聴診・触診・神経学的検査…） |
| 40〜62 | 診断（**40・41は「多発病名(病院設定)」＝院内頻用病名の枠**） |
| 80以降 | 処置（＝会計データ） |

`syori1_id` 0〜79 が文例、80以降が会計という切れ目があった。`msgadd.php` は文字列を連結するだけで、**押した文例のIDは残っていなかった。**

**実装したもの**

- **ボタンカルテ**（`karte.html` ＋ `karte_master.json` 74KB／54分類1,837件）
  現行と同じ単純連結を踏襲しつつ、**押した文例のIDを `picks` として保存**。文例の部分一致検索、使用回数による自動並べ替え、体重・体温の数値分離
- **受診ハブ**（`visit.html`）
  同一ドメインの端末内ストレージを共有し、問診・カルテ・会計を1受診レコードに束ねる。QRカメラ読取、進行状況、紙カルテ印刷、まとめて印刷、受診記録の書き出し
- **QRラベル発行**（`qrlabel.html`）
  ホルダー用ラベルをA4に並べて印刷。CSV一括取り込み、重複警告、サイズ・列数・枚数の設定
- **ネットレジ v0.7**
  明細のどの行でも修正・削除／確定後の再発行／取消（記録は残し集計から外す）

**修正した重要な不具合**

| 症状 | 原因 |
|---|---|
| 「済」が付かない | ハブが受診レコードを保存する前にツールを開いていた |
| 戻ると患者が消える | 「ハブへ」以外の戻り方でURLにキーが付かない |
| カルテを開き直すと消える | 読み込まずに書き戻していた（**データ消失の危険**） |
| QRが読めない | QR生成の既定変換が1バイト文字用で**日本語が落ち中身が空**だった |

**そして深夜、日付をまたいだ。**

編集中の受診の日付と端末の日付がずれ、その日の売上が2日に割れた。暦の日付で締めていたのが誤りで、**「営業日」の概念を導入**（`DAY_START`：その時刻までは前日扱い）。あわせて過去日をさかのぼって確認・印刷・集計できるようにした。

## 総括

9日間でやったことは、発明ではなく**移し替え**だった。

キー配置がテーブルにあり、マスタが名称だけを持ち、業務ロジックが1ファイルに集まっていた。だから `msgnew2.php` の判定チェーンがそのまま JavaScript になり、`item` の126件がそのまま画面のキーになり、`syori2` の1,837件がそのままボタンになった。**元の設計が正しかったから移せた。**

変わったのは置き場所だけである。サーバの中にあったものがタブレットの中に移った。それだけで、必要なものが専用機とサーバからブラウザ1つになり、同時に「押した文例のIDを残す」「営業日で締める」といった、当時できなかったことが加わった。

残る作業は、保険と傷病名、そして飼主への受け渡しである。
